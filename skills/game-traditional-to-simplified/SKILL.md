# 游戏官方繁体转简体

将官方繁体中文无损导出、用本地 OpenCC 转换，再封装成能独立启用和关闭的 MOD。优先复用可信开源工具，默认 `tw2sp`，用 `t2s` 对照审阅术语，不逐句调用模型翻译。

## 默认自动执行

用户只需指出游戏和目录，Codex 自行检测、获取可信依赖、调用后台脚本、校验并交付；不要求用户打开管理器、敲命令或手动导入导出。仅用于已有官方繁体中文转简体。用户需要一键程序时，交付负责已验证繁简资源启用/恢复的工具，不扩展为其他语种翻译或通用 MOD 管理器。

处理《镜之边缘：催化剂》时先读 [references/automation.md](references/automation.md)，优先直接执行已验证的 [scripts/auto_catalyst.py](scripts/auto_catalyst.py)。它无需 Frosty Mod Manager，通过官方资源库在后台完成构建。其他游戏先确认对应适配器，不假定一个脚本支持全部游戏。安装或启动仍遵守已授权范围；缺少自动接口时明确报告具体限制。

## 工作边界

- 先只读识别游戏、引擎、版本、当前语言及工具支持。原文备份、转换、字体和打包都放在独立工作目录。
- 不修改 EXE、绕过 DRM、盲替换 SB/TOC/CAS 等容器、删除原资源或上传游戏文件。仅从已核实的官方发布源获取工具；不运行来源未知的程序或插件。
- 写入游戏目录、修改启动参数、执行管理员命令前，确认用户已授权对应动作；现有明确授权可继续使用，制作 MOD 本身不等于授权安装。
- 无可靠导出/导入路径时停止构建，保留文本及报告，明确缺少哪一项能力，不猜测格式反复试写。

## 工具名称与适配范围

交付 Windows 一键工具时统一使用 `GameChineseConverter.exe`，窗口标题为“游戏繁简转换工具”。主界面不显示“当前适配”或游戏名称，副标题仅保留版本、离线安装与恢复说明，不用游戏缩写命名主程序。游戏识别、版本与资源适配检查留在后台；实际支持范围写入交付说明，不能把通用外观描述为已支持所有游戏。

skill 的流程、OpenCC 和验证能力可复用于不同游戏；每个交付 EXE 的后端与内置资源属于已适配的游戏。先实际检测引擎、官方繁体资源、导出/导入接口、字体和加载方式，再生成该游戏的同名工具。未知游戏不能只换名称或路径就套用 Catalyst 的资源编号、Steam App ID、MOD 数据目录或加载参数；未适配时明确说明限制。

## 四项独立验证

1. **文本正确**：ID、数量、顺序、重复行、资源关联、非中文字符、占位符和换行一致。
2. **编码可表示**：引擎字符串编码表能表示所有目标字符；编码表扩展不能代替字体检查。
3. **字体完整且一致**：实际语言字体有字形；同一句汉字不能意外混用不同字体或字重。
4. **MOD 实际加载**：包有效、管理器已应用且启用、生成数据包含此版本、游戏显示验证通过。

一项通过不能替代其他项。用户截图和运行反馈属于游戏内证据，记录来源与覆盖范围；仅有离线读回不能报告“汉化成功”。

## 执行流程

### 识别与无损导出

确认游戏身份，不凭惯用路径猜语言文件。记录实际资源路径、类型、语言、ID 类型、版本和工具来源。用官方 SDK、成熟导出器或已审查的开源扩展，核实导出和导入是否真实支持批量操作。

导出原表全部行及顺序，不能先转成按 ID 去重的字典。原资源相同 ID/相同文本重复时保留重复行；同 ID/不同文本需调查上下文，不能静默覆盖。多语言资源分开处理。

Frostbite/Frosty 项目此时阅读 [references/frostbite.md](references/frostbite.md)。其他引擎核实自身导入器，不能套用 Frostbite 格式或编号。

### 本地转换

阅读 [references/text-schema.md](references/text-schema.md)。隔离环境装官方 OpenCC，先跑样本及 [scripts/test_conversion.py](scripts/test_conversion.py)，再用 [scripts/convert_localization.py](scripts/convert_localization.py)。脚本接受规范化 JSON，不解析游戏容器。

- 保护实际引擎的占位符、标签、转义和控制字符，仅转换汉字；按导出样本补保护规则，不把普通可见括号内容一律当变量。
- 优先 `tw2sp`；抽样对照人名、地名、说话者前缀及 UI 专名。词典把名字改成另一语义时，用明确的小术语表保留官方名字的字形转换，不重译。
- 原文只读，输出逐字节备份、独立简体 JSON、tw2sp/t2s 对照和统计报告。重复运行不得覆盖不同来源的原文备份。
- 保留原有合法空文本，不补剧情；检查新增空文本、替换字符和无效 Unicode。繁体残留仅作候选审阅，不自动改专名或受保护内容。

### 编码与字体（打包前）

阅读 [references/fonts.md](references/fonts.md)，确认实际语言绑定的字体和回退链。

- 分别统计编码表缺字和字体 cmap 缺字，以及受影响条目数。
- 缺简体字时优先统一汉字字体。只给缺字补另一字体虽能显示，仍可能造成同句粗细、字形和视觉大小不一致。
- 标准 TrueType 可用 [scripts/font_tools.py](scripts/font_tools.py) 的 `audit` 和 `unify`；未知封装、CFF、贴图字库采用可靠的对应工具，不强行套此脚本。
- 保留英文、数字、图标、PUA、资源关联和原 UI 层级。统一汉字设计而非强制全界面同字号。检查 UPEM、字宽、行距、基线和栅格化样本，生成对照图。

### 构建、应用与游戏内验证

按可靠导入路径维护资源引用与大小字段。输出独立 MOD 和可编辑项目；修复用新文件名、标题和版本。官方读取接口读回包，检查 profile/version、类型、资源数、关联、哈希和解压 payload。

优先由 Codex 使用可靠后台接口执行已获授权的应用。只有确实需要人工 GUI 时才指导具体点击，以当前截图为准。Frosty 的 **Available Mods 只表示导入**；还要 **Apply Mod(s)**，在 **Applied Mods** 中存在且勾选，再从管理器启动。更新时停用旧中文/字体包。 用户要求默认从 Steam 启动简体时，按已授权范围保存已核实的 MOD 数据路径启动参数，备份、保留原参数并读回；具体做法见 references/automation.md。配置检查与实际启动验证分别记录。

仍繁体先核对应用列表、生成清单、版本和启动链；缺字/方框核对编码、字体和实际覆盖；粗细不一致检查字体混用。只按证据修复，重测受影响步骤。

游戏内核对主菜单、设置、地图、任务、技能、字幕、加载提示：完整显示、粗细一致、断行与截断。区分“用户确认可用”“样本通过”和“全游戏校对完成”。

## 交付与日志

交付原文备份、简体、术语表、脚本、字体/资源报告、独立 MOD（成功时）、中文加载与关闭说明。保留工具版本、配置、来源、校验值及未验证项；不能将游戏资源混入可分享的 skill 包。

日志仅输出统计和少量异常 ID，不打印整库。本次 Catalyst 已验证经验见 [references/catalyst-case.md](references/catalyst-case.md)，仅处理该游戏或复核经验时阅读。
