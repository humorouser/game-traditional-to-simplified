# 功能与平台范围

## Skill 做什么

用户提供游戏和目录后，Codex 依据 skill 检测真实资源结构，选择可靠的导出/导入路径，在独立工作目录转换和打包，输出原文备份、对照表及报告。只有已有官方繁体文本才能做本项目的字形与用语转换。OpenCC tw2sp 优先，t2s 用于比较，专名通过小术语表审阅。

## 哪些部分通用

规范化文本转换、占位符保护、ID/顺序/非中文检查，以及字体覆盖检查可以复用。游戏资源容器、编码表、实际字体绑定、资源导入和启动方式各有差异，需要适配器。不能拿 Catalyst 的 Steam AppID、资源 GUID、7978 行断言或 dataPath 参数套其他游戏。

游戏来源于 Steam、Epic、EA App、GOG 或独立安装，并不决定文本能否转换；决定因素是资源格式及可靠的加载路径。但本仓库目前只验证了 Steam Catalyst 的完整构建，不声称已经支持其他平台。

## 一键 EXE 做什么

本地案例 EXE 安装已生成的独立简体资源，保留原资源；能够撤销自己增加的加载参数恢复繁体。它不会现场调用模型翻译，也不会把未知游戏自动转成简体。

当前案例的 Steam 账户数字是本机 userdata 配置目录标识，用于选择保存启动选项的账户，不是密码或 OpenCC 转换输入。“从 Steam 启动游戏”按钮只启动这个适配器指定的游戏。统一平台识别、隐藏账户并提供通用启动按钮是可改进的方向，当前程序尚未实现多平台界面。

## 自动化的实际边界

auto_catalyst.py 自动导出、转换、处理编码/字体、校验并打包。安装、ModData 生成和启动配置由 Codex 在获得对应授权后单独处理。当前 skill 不带一键 EXE 的模板、构建脚本或补丁载荷。

界面文字显示“已配置”只代表加载配置通过检查；必须用真实游戏画面和反馈确认是否加载及显示完整。字体缺字、编码缺字、MOD 未启用和混合字重分别检查，不互相代替。
